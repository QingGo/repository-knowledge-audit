# R9 reference-check report — real repositories (2026-11-09)

Rule: **R9 "reference check"** (kblint v0.2.1, deterministic, stdlib-only, zero network).
Scope: KB claims that point at repository artifacts which do not exist — local markdown links,
backticked repo-relative paths, `make <target>` (root Makefile), `npm|pnpm|yarn run <script>`
(root package.json). This report records the real-repo validation required by the rule spec:
confirmed findings, manual false-positive assessment, the tightenings they motivated, and the
known limits. It is **not** a precision/recall population estimate (3 repos, manual adjudication,
KB-surface configs chosen by hand).

## Method

Three read-only repositories on this host, each scanned three ways:

```bash
cd kb-health/kblint
# (a) KB surface, generic: only agent knowledge files are in the doc surface
python3 -m kblint scan --repo /HOME/code/<repo> --config /tmp/kb.json \
    --out /tmp/out --format json,md,sarif --now 2026-11-05
#     /tmp/kb.json = {"repo": "...", "docs": ["AGENTS.md","CLAUDE.md","docs/AGENTS.md"],
#                     "git": {"enabled": false}, "now": "2026-11-05",
#                     "references": {"enabled": true}}
# (b) KB surface + the committed example config (references.allow_missing for runtime/model dirs)
python3 -m kblint scan ... --config examples/references.kblint.json ...
# (c) for R4 only: all-markdown surface (to measure the out-of-contract product-doc noise)
#     docs = ["AGENTS.md","CLAUDE.md","docs/**/*.md"]
```

Every R9 finding below was opened in the source doc and adjudicated by hand against the repo tree
(no network, no checkout mutation; the repos were only read). "TP" = the doc really points at an
artifact absent from the repo; "FP" = the reference is out of contract (another project's path,
runtime/generated artifact, example, or link stub).

## False-positive classes and the tightenings they motivated

| class | example (real) | fix |
|---|---|---|
| illustrative/other-project path | R4 `AGENTS.md#L11` `layouts/page.html` ("e.g."); R4 product docs `content/about/index.md`, `_default/list.html` | lines carrying `e.g.`, `for example`, `such as`, `例如`, `示例`… are skipped for link/path checks (−18 findings on R4 all-docs, incl. all 4 KB-surface FPs) |
| link stubs / bare words | R4 docs `[Language](g)` | link targets must look path-like (contain `/` or `.`); bare words ignored |
| runtime / model / generated artifacts | R2 `artifacts/last_profile.json`, `weights/tokenizer.json` | per-repo `references.allow_missing` regex list (+ `inventory` for external-but-known); documented recipe, not a hidden default |
| product documentation (user-project paths) | all 64 R4 all-docs findings | out of contract by design: scope `docs` globs to the KB surface (example config) |
| same target in two docs collapsed | cross-doc duplicates | `cli._dedupe`: claimless findings dedupe per `(doc, locator, subject)`, +2 findings retained on R4 |

Deliberately **not** "tightened" (documented limits instead): bare filenames/directory names,
paths inside fenced code blocks (tree diagrams / pasted output), and illustrative-marker lines can
hide real stale references — that is the conservative price of keeping precision on convention-heavy
KB docs. Removing whole directories *is* still flagged (`R2 docs/*` has no `docs/` dir).

## Determinism and cost

- 3 repeated scans of R4 (1023 docs, 65 total findings / 64 R9) are byte-identical:
  `sha256(findings.jsonl)` identical across runs; scan is clock-free (`--now` pinned).
- R4 all-docs scan ≈1 s wall on this host; R9 itself is filesystem-existence only (the
  filesystem walk dominates). No network, no subprocess except none (git disabled in these configs).
- Tests: `python3 -m pytest -q` → **29 passed** (16 pre-existing + 13 new R9 tests).

## Recommendations / known limits

1. Aim R9 at the **knowledge surface you own** (`AGENTS.md`, `SKILL.md`, `docs/AGENTS.md`), not at
   product/user documentation; see `examples/references.kblint.json`.
2. Add `allow_missing`/`inventory` for runtime, generated, model, or externally-fetched artifacts
   instead of waiving findings; the suppression is visible in config and reruns deterministically.
3. R9 findings are broken **evidence pointers** (`medium` path/link, `low` make/npm), not proof the
   claim is false; an existing referenced file is not proof the claim is correct.
4. Precision/recall here are manual and small-n (3 repos, KB-surface configs). The hidden FP risks
   are external paths that look repo-local and illustrative lines; the hidden FN risks are fenced
   examples and bare names.
