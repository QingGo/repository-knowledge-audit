# PROTOCOL — natural-checkout audit of real repository KBs (task-85)

**Question.** The paper's linter evidence so far comes from *controlled mutation* of healthy
repositories (S6.17): injected breakages are detected, but a reviewer can ask whether the checker
finds **natural** repository-knowledge drift in checkouts it has never seen. This protocol fixes the
sampling, fetching, scanning and adjudication rules **before** looking at results.

**Constraints.** Zero LLM/API calls for analysis (only public GitHub metadata + tarball fetches); no
source-repo clone (git clone blocked on this host); everything read from pinned, hash-addressed
tarballs; single annotator (no inter-annotator agreement); timebox ~3 h.

## 1. Sampling frame

Frame: the 76 public repositories already scanned in
[`../../real_scan/scan_rows.json`](../../real_scan/scan_rows.json) (root `AGENTS.md`/`CLAUDE.md`, 5,620
kblint claims; popular-repo sample; lower bound, not a population sample).

**Stratification (20 target repositories).** Cells = manifest class × claim-count band × KB-file type:

- manifest class: `node` (root `package.json`, no Python/Cargo/Go manifest), `python`
  (`pyproject.toml`/`requirements.txt`/`setup.py`), `other` (remaining, e.g. `Cargo.toml`, `go.mod`,
  `Makefile`-only, no manifest);
- claim band from the prior kblint extraction: `low` < 40, `mid` 40–90, `high` > 90;
- KB type: `AGENTS` vs `other` (`CLAUDE.md`/`.github/copilot-instructions.md`).

Slot quotas (sum = 20): node 7 (low 2, mid 2, high 3), python 7 (low 2, mid 2, high 3), other 6
(low 2, mid 2, high 2); `other`-KB-type slots are spread across classes (target ≥4 non-AGENTS).
Within each cell, candidates are ordered by a deterministic star-spread (alternating between the
below-median and above-median halves, nearest-to-median first), so the selected set is **not only
high-star**. 18 reserve candidates are kept for replacements; the selection is reproducible from
`run_pipeline.py select` → `selection.json`.

**Fetching order.** Repositories are fetched in ascending "likely-small" order (a deterministic
name-based heuristic: skills/prompts/notes/plugin/checklist-like repositories first), because tarball
size cannot be known without fetching; tarballs are capped at **12 MiB** and a failed/oversize
download is recorded as a skip with its replacement (see `fetch_meta.json.skipped`). Tarball size and
file count are recorded per repo; the sample is therefore slimmer than the frame on average — a
deliberate deviation, recorded rather than hidden.

**Pinning.** For every repository the default-branch HEAD SHA is resolved once through
`https://api.github.com/repos/<owner>/<repo>/commits?per_page=1`, and the tarball is downloaded by
that SHA: `https://codeload.github.com/<owner>/<repo>/tar.gz/<sha>`. The SHA is recorded in
`fetch_meta.json`, in each `raw/<repo>/meta.json`, and in the fragment/report. No branch names or
moving refs are used after pinning.

## 2. Scan configuration

Per repository (`configs/<slug>.kblint.json`, generated by `run_pipeline.py scan`):

- `docs` = the repo's KB file (root `AGENTS.md`/`CLAUDE.md`/`.github/copilot-instructions.md`) plus
  any of `AGENTS.md`, `CLAUDE.md`, `docs/AGENTS.md`, `GEMINI.md` that exist in the checkout;
- `references.enabled = true` with `check_paths`, `check_links`, `check_make`, `check_npm = true`;
- `references.allow_missing` = common runtime/generated trees (`node_modules`, `dist`, `build`,
  `artifacts`, `weights`, `runs`, `data`, `checkpoints`, `cache`, `coverage`, `target`, `venv`, …)
  and `*.lock`/`*.log`/`*.pid` (the committed config suppresses generated paths by contract);
- `git.enabled = false` — tarballs have **no `.git`**, so R7 (untracked/no-owner knowledge files)
  **cannot run** and is reported as unavailable, not as zero;
- `rules.R4 = false` (missing-supersedes is experimental, off by default; no repo manifest in this
  sample supplies the chronology R4 would need);
- `now = 2026-11-09`; `--fail-on none` so every scan exits 0 and paper analysis is not gated by
  severity;
- kblint v0.2.1 (kb-health/kblint), deterministic, stdlib-only, offline.

Command (per repo; exact copy in `raw/<slug>/meta.json`):

```bash
cd kb-health/kblint
python3 -m kblint scan --repo /tmp/natural_audit/repos/<owner__repo> \
  --config /REPOS_ROOT/kb-health/analysis/natural_checkout_audit/configs/<slug>.kblint.json \
  --out /REPOS_ROOT/kb-health/analysis/natural_checkout_audit/raw/<slug> \
  --format json,md,sarif --fail-on none --now 2026-11-09
```

Recorded per repo: commit SHA/date, tarball bytes, files, docs scanned, claims extracted, findings
total and by rule, R9 findings, audit-queue rows, runtime, exit code, output hashes.

## 3. Adjudication (single annotator)

### 3.1 Every R9 finding (broken reference pointer)

Rule-assisted deterministic adjudication against the extracted tree; every row is stored in
`adjudication.jsonl` (`adjudication_type = "R9_finding"`).

- **Path/link** (`file path`/`markdown link does not exist`): re-check the target at both resolutions
  the rule specifies (doc-relative and repo-root). If it exists → `false_positive` (with the resolved
  location as evidence). If absent and the target is under a declared runtime/generated tree or is a
  lock/log/pid → `runtime_unavailable` (config-contract gap, counted separately from stale). Otherwise
  → `true_stale` (broken pointer to a repo artifact that is not in the checkout).
- **make / npm** (`make target`/`package script does not exist`): re-parse the root `Makefile`
  (targets + `.PHONY`) or root `package.json` scripts with the same conservative parser; exists →
  `false_positive`, absent → `true_stale`.
- **Manual review.** Every `false_positive`/`runtime_unavailable` row and a 20% random sample of
  `true_stale` rows are opened and re-checked by hand (locator + evidence); classes are corrected if
  the rule-assisted label is wrong. R9 findings are **broken evidence pointers**, not claims that the
  KB content is wrong.

### 3.2 Audit-queue sample (unverified claims)

A deterministic random sample (seed `20261109`) of up to 150 claims
from all repos' `audit_queue.jsonl`, capped at 10/repo, is adjudicated against the tree
(`adjudication_type = "audit_queue_claim"`):

- extract checkable witnesses from the claim text and its `observed` kinds: backticked repo-relative
  paths, markdown links, `make <target>`, `npm run <script>`;
- if a witness exists and resolves in the tree → **Verified**; if it resolves nowhere (and is not a
  declared runtime path) → **Stale**; if the claim carries no tree-checkable witness → **Unknown**
  (numeric results, design judgments, negative results, procedural rules);
- the audit queue is an **Unknown-risk list, not a defect list**; `surface-flagged` (queue) counts are
  reported separately from confirmed stale counts throughout.

## 4. Statistics (pre-declared)

- per-repo: claims, audit-queue rows, R9 findings, true stale / false positive / runtime-unavailable /
  unknown, runtime, exit, SHA, sizes;
- aggregate: repos, claims, audit-queue rows, R9 findings, TP/FP/runtime, precision
  `TP/(TP+FP)` with exact **Clopper–Pearson 95% CI**; confirmed-stale rate `TP/R9` with exact CP CI;
  number/distribution of repos with ≥1 confirmed stale; adjudicated-queue sample: n, Verified/Stale/
  Unknown counts and rates, stale-rate CP CI;
- **separations kept explicit**: review candidates (queue) ≠ checked claims ≠ confirmed stale;
  R9 findings are pointers, not content defects; "surface-flagged" never reported as "stale".

Exact CP intervals use `scipy.stats.beta.ppf` (two-sided 95%). Runtime is wall clock of the kblint
subprocess; scan outputs are byte-identical for a fixed checkout (kblint determinism; no `--now`
variation).

## 5. Known limits (declared up front)

1. Convenience sample of 20 repositories from a popular-repo frame; not a population or prevalence
   estimate; stars/manifest mix is stratified but the sample is small.
2. Tarballs have no `.git`: R7 unavailable everywhere; git-history questions (when did the reference
   break?) are out of scope.
3. R9 scope is config-dependent (KB docs only; `allow_missing` contract); precision is conditional on
   that declared scope, not a global property of the rule.
4. Single annotator, rule-assisted; no inter-annotator agreement; adjudication rules are stated above
   so errors are auditable.
5. Tarball-size cap (12 MiB) and small-first ordering bias the fetched set toward smaller repos; skips
   and replacements are listed.
6. No LLM calls: adjudication is deterministic/manual, not model-assisted; no claim about coding
   outcomes or downstream harm.

## 6. Amendments after execution (documented, not silently applied)

1. **Fetched sample is 16 repos, not the 20-slot plan.** `git clone` is blocked and codeload
   throughput made large tarballs infeasible; the sample was fetched small-first with a **15 MiB**
   tarball cap. Two fetch waves attempted 44 candidates: 14 succeeded (plus 2 pipeline-pilot repos
   seeded from the same pinned tarballs), 14 were replaced after oversize/timeout failures, and the
   second wave was stopped once 16 repos were available. The final composition is node 4 / python 3 /
   other 9 (AGENTS.md 13, CLAUDE/copilot 3); the prior claim-band mix is low/mid (the fetched set has
   no >90 prior-band repo), but the current wider docs scope yields four high-extraction repos
   (caveman 286, mcp-servers 186, HowToLiveBetter 107, ai-job-search 99), so high-claim KBs are
   represented at scan time. The complete skip list is partial (4 explicit `no extracted tree`
   entries; the rest are in shell logs) because the second wave was interrupted — stated as a limit.
2. **Adjudication classes observed and used.** In addition to `true_stale` / `false_positive` /
   `runtime_unavailable`, the manual pass used stable sub-classes of false positive: historical/removal
   mentions ("we removed …", "… (deleted)", forbidden-string lists), skill-package-relative paths
   (target exists under `skills/*/…`; root-relative R9 cannot express the package base), and
   illustrative templates (`[x](docs/x.md)`). All 28 R9 findings received an explicit single-annotator
   class and note in `manual_overrides.json`; the rule-assisted auto-classification was overridden
   where the tree/context showed these cases (this is why TP=14, FP=8, runtime=6 rather than the
   auto-pass's TP=20/FP=8 with 6 mislabelled runtime paths).
3. **Determinism.** Three repos were re-scanned into scratch dirs after the build: `findings.jsonl`,
   `audit_queue.jsonl`, `summary.md` and `report.sarif` were byte-identical. R9 counts are therefore
   reproducible; only the manual adjudication labels carry annotator judgement.
4. **Sensitivity of the 3 "moved path" findings.** `mvanhorn/last30days-skill` pointers to
   `scripts/last30days.py`, `lib/__init__.py`, `references/setup-wizard.md` exist only under
   `skills/last30days/`; they are counted `true_stale` (root-relative KB is broken after the
   restructure). If a reader judges them package-relative false positives instead, TP=11 and
   precision=11/19=57.9% — reported as a sensitivity, not silently chosen.
